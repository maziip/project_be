## 변경 목적
BE-001: Gradle 애플리케이션 골격과 wrapper를 구성하고 명령행에서 빌드·테스트한다.

① 구현 내용 
brew install gradle 
JAVA_HOME 설정
gradle init(선택: Application, Java, 21, Kotlin DSL, JUnit Jupiter) 
./gradlew build 
./gradlew run 
커밋과 push.


② 주요 설계 결정과 이유.
Kotlin DSL을 고른 이유 - 튜터 권고를 따랐고 직접 체감한 근거는 아직 없다.
JUnit Jupiter를 고른 이유 (커리큘럼 필수)
toolchain 21과 wrapper 9.7.1 (VERSIONS.md와 일치)
gradle-wrapper.jar를 커밋에 포함한 이유 (wrapper가 동작하려면 필요)

③ 테스트 방법과 결과
./gradlew build → BUILD SUCCESSFUL, 테스트 1개 통과
./gradlew run → Hello World! 출력
getGreeting()을 null로 바꿔 ./gradlew test → BUILD FAILED, AssertionFailedError at AppTest.java:12 확인 후 원복


④ 알려진 한계와 리뷰어에게 확인받고 싶은 부분
build.gradle.kts 의 toolchain 설정이 컴파일 jdk 를 21f로 고정한다.
java_home 는 gradle 자체를 띄우는 jvm 만 결정한다. 
--scan으로 빌드 정보가 gradle.com에 한 번 올라갔음. 이후 사용하지 않기로 함
확인받고 싶은 것: App.java 샘플 코드를 이대로 두어도 되는지, 다음 티켓에서 지워야 하는지
미사용 Guava 제거. 패키지를 org.example 에서 knowledgeassistant 로 변경. 두 변경 후 clean build 와 run 확인
